# Almanac

A personal recall trainer for geography and general knowledge, used by Victor on his iPhone as a home screen web app. The aim is to rebuild the memory he had in high school (every capital, including US and Mexican state capitals), for fun and without pressure.

## Design principles
- **Calm, not compulsive.** No streaks, badges, timers, notifications, or counts of missed days. A skipped week quietly reshuffles. Do not add gamification without asking.
- **Recall, not recognition.** Prompt, think, reveal, self-grade (missed / shaky / knew it). No multiple choice.
- **Context makes it stick.** Every card carries a one-line curiosity note on the reveal side.
- **Honest progress.** The only progress shown is "N of M settled" per deck.

## Structure
No build step, no dependencies. A handful of static files rather than one, because offline use on iPhone needs a manifest, icons and a service worker.

- `index.html`: the app (HTML, CSS, JS inline), plus `sky/astro.js` for the astronomy.
- `sw.js`: service worker. Network first for the app's own files (4 s timeout, then the stored copy), with `cache: 'no-cache'` to bypass GitHub Pages' 10-minute `max-age`; cache first for Google Fonts. Updates appear on the next launch. Bump `CACHE` only to force a clean cache.
- iOS suspends home screen apps rather than closing them, so `index.html` reloads itself when brought back after more than an hour (never mid-round).
- `manifest.webmanifest`, `icons/`: home screen install. Icons are drawn by `tools/make-icons.py` (Pillow).
- `decks/index.json`: list of deck ids to load. Adding a deck means adding a file and its id here; no app code changes.
- `decks/<id>.json`: one deck.
- `maps/<name>.svg` and `decks/maps.json`: generated by `tools/make-maps.py` from Natural Earth's public domain `ne_50m_admin_0_countries.geojson` (not committed; pass its path to the script). Re-run it if the world capitals deck changes. Each map is a Lambert azimuthal equal-area projection of one region, clipped and simplified; countries in the world deck get `id` = their world card id (`w-fr`); countries too small to see on a phone get `<circle class="ring" data-for="w-..">`. A map card has `map` and `target`; the app inlines the SVG and adds class `on` to the target. Disputed or non-deck territories are plain land and never asked.

## Deck format
```json
{
  "id": "us-states",
  "title": "US state capitals",
  "subtitle": "All 50 states",
  "promptLabel": "Capital of",
  "reversible": true,
  "reverseLabel": "Capital of which state",
  "context": "United States",
  "about": "Shown on the deck's browse page.",
  "cards": [
    { "id": "us-ca", "prompt": "California", "answer": "Sacramento", "note": "..." }
  ]
}
```
Optional card fields: `label` and `reverseLabel` (override the deck's), `context` (the small line under the prompt), `group` (browse page heading), `noReverse`, and for map cards `map` + `target`. World cards use the older `subregion`, which serves as both context and group.

- Card `id`s must be stable forever: progress is keyed by them. Prefixes: `w-` world (ISO alpha-2), `us-` (USPS), `mx-` (ISO 3166-2:MX), `el-` elements (symbol), `gm-` Greek myths, `ds-` discoveries, `map-` maps, `lm-` landmarks, `nz-` NZ regions, `md-` medieval, `nm-` Norse, `eg-` Egyptian, `mt-` Māori traditions, `sk-` sky and space, `mu-` music.
- Card order in the file is the order new cards are introduced, so neighbours are grouped.
- The small line under the prompt is `card.context`, else `card.subregion`, else `deck.context`, else the deck title. It disambiguates (Georgia the country vs the state).
- Notes: one durable, verified fact, 12 to 25 words, no stale statistics, no em or en dashes.
- Facts are checked against English Wikipedia before they go in.

## Scheduling (Leitner boxes)
- Intervals by box, in days: `[0, 1, 3, 7, 16, 35, 75, 150]`. Box 4 and above (16+ days) counts as settled.
- Knew it: up one box. First sighting and knew it: straight to box 3 (already known).
- Shaky: down one box, minimum 1. Missed: box 1, and the card returns a few cards later in the same round (practice only, no further state change).
- A round is capped (default 15): due cards first, most overdue first, then up to 5 new cards dealt one per deck in turn, the decks in random order each round (so no deck is starved when there are more decks than new-card slots). Backlog never shows as a number. "Another round" is always available if anything is due or unseen.
- Days are local calendar days.

## Reverse direction
- In a `reversible` deck each card also has a reversed twin, id `<id>~r`, with its own schedule: the answer becomes the prompt under `reverseLabel`.
- A reversed card unlocks once its forward card reaches box 2 (known at least once).
- No reversed card when one side contains the other (Durango, Monaco, Indianapolis), or when `noReverse` is set.
- The two directions of one item never share a round.
- Per-deck switch on the browse page, stored in `settings.revOff`. Home shows a "Reverse: N of M settled" line once any reversed card has been seen.

## The daily five
- Five cards a day, one from each of five decks, chosen by a PRNG seeded from the local date (`almanac:YYYY-MM-DD`; FNV-1a then mulberry32) over decks sorted by id. It ignores which decks are switched off, so everyone gets the same five.
- It never touches the schedule. Results go in `store.daily[YYYY-MM-DD]` as grades (about four months kept). Home shows Play, or the dots (● knew, ◐ shaky, ○ missed) with Review and Share. Share uses the share sheet, else the clipboard.

## Rabbit holes
- `buildLinks()` runs at load; no link data is stored. A card links to another when they share a name (France the capital card, France on the map, the Eiffel Tower) or when its note mentions another card's answer or prompt.
- Names come from prompt and answer, split at " · ", without parentheses, at least 4 characters, no digits. A mention must stand alone: not inside a longer capitalised name ("Nelson Mandela" is not Nelson), though a sentence-initial word next to it is ignored.
- Up to three links per card, same-name links first, spread across decks, never two buttons with the same text. Namesakes are kept on purpose (Georgia and Georgia, Saturn's moon Rhea); the button names the other side of the card, so Paris of Troy reads "Trojan prince who carried off Helen".
- Deck field `"chip": "prompt"` labels links to that deck by the card's prompt (landmarks: the landmark, not its country).
- Tapping a link opens a read-only `peek` view whose `back` is the previous view, so a round resumes exactly where it was. Peeking never touches the schedule.

## Overland journeys
- Name each country as it lights up along an overland route; never touches the schedule. Last result per named route in `store.journeys[id] = { day, results }` (surprise routes are not saved).
- `tools/make-maps.py` also builds `maps/world.svg` (Equal Earth projection, 2000 wide, no Antarctica, path `id` = world card id, an empty `<g class="labels">`) and `maps/world.json` (`{ width, height, countries: { id: { box, label, near } } }`). Both load the first time the Journeys page opens, then work offline.
- `near` (land neighbours) comes from shared border vertices, holes included (Lesotho, San Marino, Vatican City). Only a country's main territory counts: its largest polygon plus polygons chained within `NEAR` (60 units, about 1,200 km), so East Malaysia and Kaliningrad count but French Guiana does not. `box` uses a tighter chain, `NEAR_BOX` (25 units), so the Azores or the Canaries do not stretch the map window. `label` is a well-inside point of the largest polygon.
- `maps/journeys.json` holds the named routes (id, title, story, countries as world card ids). The script checks every step is a land neighbour and prints any that is not.
- Surprise me: a random start, then a shortest route (shuffled neighbours) to a country 6 to 12 countries away.
- The map window follows play (the last two countries and the current one), then shows the whole route at the end. A country more than three times the area of the rest of the window's countries (Russia, China) only pulls the window a little way towards itself. Done countries are tinted by grade and labelled, the label sized to fit or left off.
- Island nations have no land neighbours, so they never appear in journeys.

## Tonight's sky
- A planisphere for Auckland (`SKY` in `index.html`: −36.8485, 174.7633): stereographic dome, zenith at the centre, the facing direction at the bottom (default south), a time slider from sunset to sunrise in five-minute steps, "Up tonight" in plain words, tap for details and a link to the matching card. It never touches the schedule.
- `sky/astro.js` (global `Astro`): Sun and planets from Standish's JPL Keplerian elements (Table 1, 1800 to 2050); Moon from Schlyter's method with the main perturbations and topocentric parallax; precession J2000 to date (Meeus 21.2); GMST (Meeus 12.4); `crossings()` for rise and set. Checked against JPL Horizons from Auckland in 2026 and 2031: all bodies within 5 arcminutes (Saturn worst; most within 1); Sun and Moon rise and set within a minute; Moon illumination within 0.4%.
- `sky/stars.json`: Yale Bright Star Catalogue (CDS V/50), stars to V 4.5 as `[hr, ra, dec, vmag, bv]` J2000, IAU names, four verified Māori names, 27 constellation figures (simplified from d3-celestial, BSD 3-Clause, credited in the file), 11 deep-sky objects, HR to card id links. Loaded the first time the page opens.
- Rise and set: Sun and Moon at −0.833° (upper limb, refraction), planets and stars at −0.5667°. Seasonal notes: Matariki (Pleiades) and Puanga (Rigel) when up an hour before sunrise, May to July.
- Chart units: the horizon circle has radius `K` = 500, so text sizes are ordinary numbers (tiny SVG font sizes can be clamped by browsers).

## Which came first?
- Two dated events; tap the earlier. Ten pairs a run, gaps narrowing from centuries (`DUEL_GAPS`) to 3 to 10 years, the partner preferably from another deck. Never touches the schedule; nothing is stored.
- Events come from existing cards with a definite year (`datedEvents()`): discoveries (year at the end of `context`), medieval battles (`answer` is the year), music works and records (year at the end of `context`), space firsts (`context` is the year). Approximate dates (`c. 1021`, `1630s`, `date unknown`) are excluded. About 250 events.
- After answering, each event links to its card.

## Storage
- `localStorage` key `almanac.v1`: `{ v, cards: { id: { b, d, n, l } }, daily: { "YYYY-MM-DD": [grades] }, journeys: { routeId: { day, results } }, settings: { size, fresh, notes, off, revOff } }`. `b` box, `d` due day, `n` times graded, `l` last day. `off` lists decks excluded from rounds; `revOff` decks with reverse switched off.
- An iOS home screen app has storage separate from Safari, hence Settings has export and import.

## Local testing
`fetch` does not work from `file://`; serve the folder (e.g. `python3 -m http.server 8642`).

## Deployment
GitHub repo `vcanela/almanac-app`, GitHub Pages from `main`. All paths are relative so the app works under `/almanac-app/`.
